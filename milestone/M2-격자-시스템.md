# M2 — 격자 시스템  ✅ 완료 (2026-07-31)

보드 영역의 픽셀 크기를 받아 **몇 열 몇 행의 어떤 크기 셀로 나눌지** 계산한다.

전부 순수 함수다. React도 DOM도 모른다. 이 마일스톤의 산출물은 화면에 아무것도
그리지 않으며, 검증은 Vitest로만 한다.

**선행:** M0 (Vitest)
**예상 산출물:** `src/features/satchel/grid/` — `gridMetrics.ts`, `coords.ts`, 테스트

---

## 설계

### 왜 열 수를 먼저 정하는가

셀 크기를 먼저 고정하면(예: 88px) 기기마다 열 수가 제각각으로 떨어지고 가장자리에
어중간한 여백이 남는다. 홈화면이 그렇게 동작하지 않는 이유다.

**폭에 따라 열 수를 먼저 정하고, 셀 크기는 남은 폭을 나눠 갖는다.** 그러면 어느
기기에서든 가장자리 여백이 균일하고 셀이 화면에 꽉 찬다.

### 열 수 — 구간표를 버리고 목표 셀 크기에서 역산한다

> **계획을 바꿨다.** 애초에 폭 구간표(4/6/8/10/12열)를 두려 했으나, T2.4의 실측에서
> 넓은 화면일수록 셀이 목표 범위를 벗어났다. 1180px에서 104px, 1440px에서 107px —
> "앱 아이콘 수준"과 멀어진다. 경계를 더 잘게 나눠 막을 수는 있지만, 그러면 기기가
> 바뀔 때마다 표를 손봐야 한다.

**목표 셀 크기(84px) 하나를 두고 열 수를 역산한다.**

```
columns = clamp(round((가용폭 + 간격) / (목표셀 + 간격)), 4, 16)
```

구간표가 사라지니 경계를 관리할 일이 없고, 어느 폭에서든 셀이 비슷하게 나온다.
대신 열 수가 짝수로 떨어지지 않는다(9열·15열 등) — 위젯 보드에서는 문제되지 않고,
M3의 레이아웃은 어차피 열 수를 키로 쓰므로 값이 무엇이든 상관없다.

**격자 폭에 상한(1600px)을 둔다.** 없으면 2560px 모니터에서 열 수가 상한(16)에
걸려 셀이 147px까지 부푼다. 게다가 그 폭을 가로지르며 위젯을 끄는 것은 실제로 쓸 수
없다. 열과 셀은 상한을 씌운 폭으로 계산하고 여백은 실제 폭으로 구하면, 넓은
화면에서 격자가 저절로 가운데 놓인다.

### 행 수

행 수는 구간으로 정하지 않는다. **셀을 정사각형으로 두고, 보드 높이에 몇 개가
들어가는지로 결정한다.** 세로 공간은 기기마다 편차가 크고 툴바 위치(M5)에 따라서도
달라지므로 계산으로 뽑는 편이 맞다.

행이 0이 되는 극단(가로 모드에서 툴바가 상단일 때)을 반드시 처리한다 — 최소 1행을
보장하고, 그때는 셀이 정사각형이 아니어도 된다.

### 셀은 정사각형

위젯 크기를 `1×1`, `2×1`, `2×2`처럼 말할 수 있으려면 셀이 정사각형이어야 한다.
직사각형 셀이면 `2×2`가 기기마다 다른 비율이 되어 위젯이 설계한 모양으로 안 나온다.

## T2.1 — 격자 계산 함수

```
computeGridMetrics(board: { width: number; height: number }, options?) => GridMetrics
```

반환값에 담을 것:

- `columns`, `rows`
- `cellSize` (정사각형 한 변, px)
- `gap` (셀 사이 간격)
- `paddingX`, `paddingY` (남는 공간을 가장자리에 균등 배분)

- [x] ~~열 수를 구간표로 결정~~ → 목표 셀 크기에서 역산 (위 설계 참조)
- [x] 가용 폭에서 간격을 빼고 셀 크기 산출
- [x] 셀 크기로 행 수 산출, 최소 1행 보장
- [x] 남는 세로 공간을 상하 여백으로 배분
- [x] 소수점 처리를 정한다 — 셀 크기를 반올림하면 누적 오차로 마지막 열이 삐져나온다.
      **셀 크기는 소수로 두고 여백만 조정**하거나, 정수로 내린 뒤 잔여 픽셀을 여백에
      더한다. 후자를 권한다. 렌더링이 흐려지는 것을 막는다.

**수용 기준 (테스트로 검증):**
- 대표 기기 9종에서 셀이 72~96px 안에 들어온다
- 폭이 넓어질수록 열 수가 줄지 않는다(단조 증가)
- `paddingX*2 + columns*cellSize + (columns-1)*gap === board.width` (오차 1px 이내)
- 높이가 아주 작아도 `rows >= 1`
- 폭 0, 높이 0 같은 이상값에서 던지지 않고 안전한 값을 낸다

## T2.2 — 좌표 변환

격자 좌표 `{x, y, w, h}`(셀 단위)와 픽셀 사각형을 오간다.

```
cellsToPixels(placement, metrics) => { left, top, width, height }
pixelsToCell(point, metrics)     => { x, y }        // 가장 가까운 셀
```

- [x] `cellsToPixels` — 위젯을 절대 위치로 그릴 때 쓴다
- [x] `pixelsToCell` — 드래그 중 포인터 위치를 셀로 환산할 때 쓴다(M6)
- [x] 경계 밖 좌표를 격자 안으로 자르는 `clampToGrid`
- [x] **두 함수는 서로의 역이어야 한다.** 왕복 테스트로 검증한다.

**수용 기준:** 모든 셀에 대해 `pixelsToCell(cellsToPixels(cell).중심) === cell`.

## T2.3 — 배치 유효성 판정

M3·M6이 함께 쓸 술어들. 여기서 만들어 두면 화면 코드가 규칙을 다시 쓰지 않는다.

```
isWithinGrid(placement, metrics) => boolean
overlaps(a, b) => boolean
findFreeSpot(size, existing, metrics) => Placement | null
```

- [x] `isWithinGrid` — 격자 밖으로 나가지 않는가
- [x] `overlaps` — 두 배치가 겹치는가 (사각형 교차)
- [x] `findFreeSpot` — 주어진 크기가 들어갈 빈 자리를 찾는다. 위젯을 새로 켤 때
      어디에 놓을지 정하는 데 쓴다(M4). 좌상단부터 행 우선으로 훑고, 없으면 `null`.

**수용 기준:**
- 변이 맞닿기만 한 두 배치는 겹치지 않는다고 판정한다 (`x:0,w:2`와 `x:2,w:1`)
- 격자가 꽉 찼을 때 `findFreeSpot`이 `null`을 낸다
- 빈 격자에서 `findFreeSpot`은 항상 `{x:0, y:0}`을 낸다

## T2.4 — 실측 보정  ✅

M1에서 실측한 보드 크기(툴바를 뺀 값)를 넣어 뽑은 표다.

| 기기 | 보드 | 열×행 | 셀 | 좌우여백 |
|---|---|---|---|---|
| iPhone SE | 375×603 | 4×6 | **78px** | 13.5 |
| iPhone 15 | 393×788 | 4×8 | **83px** | 12.5 |
| 갤럭시 S24 | 360×716 | 4×8 | **75px** | 12.0 |
| 폰 가로 (상단 툴바) | 852×329 | 9×3 | **81px** | 13.5 |
| 폰 가로 (좌측 툴바) | 796×393 | 8×3 | **86px** | 12.0 |
| iPad 세로 | 820×1116 | 8×10 | **89px** | 12.0 |
| iPad 가로 | 1180×756 | 12×7 | **85px** | 14.0 |
| 데스크톱 | 1440×836 | 15×8 | **83px** | 13.5 |
| 와이드 | 2560×1300 | 16×13 | **87px** | 494.0 |

셀이 **75~89px**로 고르다. 와이드에서 여백이 494px인 것은 격자 폭 상한(1600px)에
묶여 가운데 놓였다는 뜻이다.

**M5로 넘기는 결과 — 폰 가로에서 툴바 위치가 행 수를 바꾸지 않는다.**
상단 툴바 9×3, 좌측 툴바 8×3으로 둘 다 3행이다. 계획서는 "상단 툴바면 행이 1~2개로
줄어들 것"이라 보고 좌측 기본값의 근거로 삼으려 했으나 **그 근거는 성립하지 않는다.**
좌측이 열을 하나 줄이는 대신 셀을 키우는(81→86px) 맞바꿈일 뿐이다. M5는 다른 근거로
정해야 한다.
