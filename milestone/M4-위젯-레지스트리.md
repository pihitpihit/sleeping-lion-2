# M4 — 위젯 레지스트리와 Test 위젯  ✅ 완료 (2026-07-31)

위젯을 등록하는 규약을 정하고, 첫 위젯인 Test를 만들어 보드에 그린다.

이 마일스톤이 끝나면 **위젯이 화면에 보인다.** 다만 아직 옮기거나 크기를 바꿀 수는
없다(M6).

**선행:** M3 (레이아웃 스토어)
**예상 산출물:** `src/features/satchel/widgets/` — 레지스트리, `TestWidget`, 렌더러

## T4.1 — 위젯 정의 규약

```ts
interface WidgetDefinition {
  id: string                     // 'test'. 저장된 레이아웃의 키가 되므로 바꾸면 안 된다
  name: string                   // 툴바에 보일 이름. 화면 문구이므로 여관 문체를 따른다
  defaultSize: { w: number; h: number }
  minSize: { w: number; h: number }
  maxSize?: { w: number; h: number }   // 없으면 격자 크기까지
  maxInstances?: number                // 없으면 무제한
  Component: ComponentType<WidgetProps>
}

interface WidgetProps {
  instanceId: string
  /** 이 위젯이 차지한 셀 크기. 내용 밀도를 바꾸는 데 쓴다. */
  size: { w: number; h: number }
  /** 편집 중에는 위젯이 상호작용을 받지 않는다. */
  mode: 'play' | 'edit'
}
```

- [x] 타입 정의
- [x] 레지스트리 — id로 정의를 찾는 맵과 목록
- [x] **`id`는 저장 데이터의 일부라는 것을 주석으로 남긴다.** 이름을 바꾸면 기존
      배치가 전부 알 수 없는 위젯이 된다(M3의 T3.3이 버려준다).
- [x] 등록된 정의를 검증한다 — `minSize <= defaultSize <= maxSize`인지. 어긋난
      정의는 개발 중에 즉시 드러나야 한다.

**`mode`를 위젯에 넘기는 이유:** 편집 중에는 위젯 내부의 버튼이 눌리면 안 된다.
드래그하려고 잡았는데 카드가 뽑히면 곤란하다. 위젯이 스스로 판단하게 하지 말고
**컨테이너가 포인터 이벤트를 막는 것**을 기본으로 하되(M6), 위젯이 표시를 바꾸고
싶을 수 있으므로 정보는 넘긴다.

## T4.2 — Test 위젯

배치 실험 전용. **아무 기능이 없다.**

- [x] `id: 'test'`, `name: 'Test'`
- [x] `defaultSize: { w: 2, h: 2 }`, `minSize: { w: 1, h: 1 }`, 최대 제한 없음
- [x] `maxInstances` 없음 — 여러 개 놓고 겹침·재배치를 시험해야 한다
- [x] 생김새: 테마에 맞는 사각형. 테두리와 옅은 바탕만. 글룸헤이븐 팔레트를 쓰되
      실제 위젯들과 구분되게 **의도적으로 밋밋하게** 둔다.

**격자 좌표 표시는 넣지 않는다.** (결정 완료) 명세대로 아무것도 그리지 않는
빈 사각형으로 둔다. 배치 확인은 화면을 눈으로 보고, 정확한 좌표가 필요하면
M2·M3의 순수 함수 테스트로 확인한다.

- [ ] **넣지 않음.** 검토했으나 Test는 "아무 기능 없는 빈 사각형"이라는 명세를
      지키기로 했다. 여러 개를 구분해야 할 일이 생기면 그때 넣는다.

**수용 기준:** 레이아웃 데이터에 Test 위젯을 손으로 넣으면 지정한 위치와 크기로
화면에 그려진다.

## T4.3 — 보드 렌더러

- [x] 현재 레이아웃의 위젯 목록을 훑어 각각을 절대 위치로 배치한다.
      위치는 M2의 `cellsToPixels`가 계산한다 — **렌더러가 좌표 산술을 다시 하지
      않는다.**
- [x] 알 수 없는 `definitionId`는 건너뛴다(M3에서 이미 걸러지지만 방어)
- [x] 위젯 컨테이너에 공통 껍데기를 씌운다 — 테두리, 배경, 모서리 처리. 위젯 각자가
      배경을 그리면 보드가 잡탕이 된다.
- [x] 위치 변화에 트랜지션을 줄지 정한다. 편집 중 스냅될 때 부드러우면 좋지만
      드래그 중에는 지연으로 느껴진다. **드래그 중에는 끄고 스냅 확정 때만 켠다.**

**수용 기준:**
- 위젯 여러 개가 겹치지 않고 지정한 셀에 정확히 놓인다
- 창 크기를 바꾸면 위젯이 새 셀 크기에 맞춰 다시 그려진다
- `prefers-reduced-motion`에서 트랜지션이 꺼진다

## T4.4 — 위젯 켜고 끄기

툴바 UI는 M5에서 만들지만, **동작 자체**는 여기서 만든다.

- [x] 위젯 추가 — `findFreeSpot`(M2)으로 자리를 찾아 `defaultSize`로 놓는다
- [x] 자리가 없으면 추가하지 않고 **이유를 알린다.** 조용히 실패하면 버튼이 고장난
      것으로 보인다.
- [x] 위젯 제거 — `instanceId`로 지운다
- [x] `maxInstances`에 도달한 정의는 추가를 막는다

**"토글"의 의미를 정한다.** 위젯 종류마다 켬/끔인가, 아니면 여러 개를 더할 수
있는가. Test는 여러 개가 필요하므로 **토글이 아니라 추가**여야 한다.
→ 툴바 버튼은 `maxInstances === 1`이면 토글로, 아니면 추가 버튼으로 동작한다.
M5에서 이 구분이 UI로 드러나야 한다.

**수용 기준:** 코드로 추가/제거를 호출하면 보드와 localStorage에 반영된다.
