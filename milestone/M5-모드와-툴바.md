# M5 — 모드와 툴바

편집 모드와 플레이 모드를 나누고, 툴바를 세운다.

**선행:** M4 (위젯 추가/제거 동작)
**예상 산출물:** `src/features/satchel/mode/`, `src/features/satchel/toolbar/`

---

## 모드 정의

| | 플레이 모드 | 편집 모드 |
|---|---|---|
| 격자 | **안 보인다** | 보인다 |
| 위젯 조작 | 위젯을 **사용**한다 | 위젯을 **다룬다** (이동·크기·제거) |
| 위젯 내부 상호작용 | 받는다 | **막는다** |
| 툴바 | 햄버거 + 편집 전환**만** | 전체 (햄버거 + 위젯 목록 + 플레이 전환) |

**진입은 항상 플레이 모드.** [결정 4](./README.md#결정-4--진입-시-항상-플레이-모드) 참조.

---

## T5.1 — 모드 스토어

- [ ] `'play' | 'edit'` 상태와 전환 동작
- [ ] **영속하지 않는다.** 이건 설정이 아니라 지금 무엇을 하는 중인가에 대한 상태다.
- [ ] 편집 모드에서 빠져나올 때 저장을 확정한다(M3의 쓰기 묶음과 맞물린다)

---

## T5.2 — 툴바 위치와 기기별 기본값

요구사항: 상단/좌측을 설정으로 바꿀 수 있고, 기기 유형에 따라 기본값이 다르다.

### 기본값 규칙

세로 공간이 귀한 화면일수록 툴바를 옆으로 돌린다.

| 조건 | 기본 위치 | 이유 |
|---|---|---|
| 세로 방향이고 폭 < 768px | **상단** | 폰 세로는 폭이 귀하다. 좌측 툴바가 격자 열을 잡아먹는다 |
| 가로 방향이고 높이 < 500px | **좌측** | 폰 가로는 높이가 귀하다. 상단 툴바면 행이 1~2개로 줄어든다 |
| 그 외(태블릿·데스크톱) | **좌측** | 세로 공간을 격자에 준다 |

- [ ] 판정 함수를 순수 함수로 뽑는다 (`defaultToolbarPosition(viewport) => 'top' | 'left'`)
- [ ] **기기 종류(User-Agent)로 판단하지 않는다.** 뷰포트 크기와 방향으로만 정한다.
      UA 판별은 틀리고 낡는다. 아이패드가 데스크톱 UA를 보내는 문제도 있다.
- [ ] 사용자가 한 번이라도 직접 고르면 그 값이 이긴다. 이후 회전해도 바뀌지 않는다 —
      기본값이 계속 덮어쓰면 설정이 무의미해진다.
- [ ] M2의 T2.4 실측 결과(폰 가로에서 상단 툴바 시 행 수)로 이 표를 검증한다

**수용 기준:**
- 폰 세로에서 상단, 폰 가로에서 좌측으로 열린다
- 직접 좌측으로 바꾼 뒤 회전해도 좌측을 유지한다
- 툴바 위치가 바뀌면 보드 크기가 바뀌고 격자가 다시 계산된다(M1의 ResizeObserver)

---

## T5.3 — 툴바 셸

- [ ] 상단/좌측 두 방향을 같은 컴포넌트로 그린다. 방향은 CSS로 처리하고 마크업을
      복제하지 않는다.
- [ ] 안전 영역 처리 — 좌측 툴바는 `env(safe-area-inset-left)`, 상단은 `-top`
- [ ] 터치 목표 크기를 확보한다. 버튼 최소 44px. 플레이 중 급하게 누르는 화면이다.
- [ ] 툴바가 보드 영역을 침범하지 않게 한다 — 겹치면 위젯이 가려진다

---

## T5.4 — 플레이 모드 툴바

- [ ] 햄버거 버튼
- [ ] 편집 모드 전환 버튼
- [ ] **그 외에는 아무것도 없다.** 플레이 중에는 화면이 조용해야 한다.

---

## T5.5 — 편집 모드 툴바

- [ ] 햄버거 버튼
- [ ] 플레이 모드 전환 버튼
- [ ] 위젯 목록 — 레지스트리를 훑어 버튼을 만든다
  - `maxInstances === 1`인 정의는 **토글**(켜짐/꺼짐 상태 표시)
  - 그 외는 **추가 버튼**(누를 때마다 하나 더)
  - 이 구분이 눈에 보여야 한다(M4의 T4.4 참조)
- [ ] 자리가 없어 추가할 수 없을 때 알린다
- [ ] 위젯이 많아지면 툴바가 넘친다 — 가로 스크롤 또는 접기. **보드를 밀어내지
      않는 방식**으로 처리한다

---

## T5.6 — 햄버거 메뉴

두 모드 공통. 자주 쓰지 않는 것들을 넣는다.

- [ ] 웰컴으로 돌아가기 (M1의 열린 질문 2를 여기서 닫을 수 있다)
- [ ] 툴바 위치 바꾸기 (상단/좌측)
- [ ] 배치 초기화 — **되돌릴 수 없으므로 확인을 받는다**
- [ ] 열림/닫힘, 바깥 누르면 닫기, `Esc`로 닫기
- [ ] 초점 가두기(focus trap) — 열려 있는 동안 탭이 메뉴 안에서 돈다

---

## T5.7 — 모드에 따른 보드 반응

- [ ] 편집 모드에서만 격자를 그린다. 격자는 **배경 레이어**이고 위젯 아래에 깔린다.
- [ ] 편집 모드에서 위젯 내부 상호작용을 막는다. 컨테이너에 `pointer-events: none`을
      위젯 내용에만 걸고 컨테이너 자신은 제스처를 받는다(M6).
- [ ] 모드 전환에 짧은 전환 효과. `prefers-reduced-motion` 존중.

**수용 기준:**
- 플레이 모드에서 격자가 보이지 않는다
- 편집 모드에서 위젯 안의 버튼을 눌러도 반응하지 않는다
- 플레이 모드에서 위젯 안의 버튼이 정상 동작한다

---

## 열린 질문

1. 편집 모드 진입을 버튼 말고 **길게 누르기**로도 열지. 홈화면 관용이라 익숙하지만,
   플레이 중 오조작 위험이 있다. 버튼만 두는 쪽이 안전해 보인다.
2. 툴바 위치에 '자동'을 둘지. 사용자가 고정한 뒤에도 회전하면 따라가길 원할 수 있다.
   `'top' | 'left' | 'auto'` 세 값으로 두고 기본을 `'auto'`로 하는 방법.
3. 편집 모드에서 되돌리기(undo)가 필요한가. 실수로 지웠을 때 복구 수단이 없다.
   최소한 제거에 확인을 받거나, 마지막 조작 하나만 되돌릴 수 있게 하는 방법.
