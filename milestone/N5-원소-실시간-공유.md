# N5 — 원소 트래커 실시간 공유

N4가 만든 빈 방에 **첫 값**을 넣는다. 원소 여섯 개의 3단계 상태가 참여자끼리
맞춰진다.

선행: N4 · 정본: [`../SPEC.md`](../SPEC.md) 5.4 · 전체 그림: [N0](./N0-네트워킹-설계.md)

---

## 왜 원소가 첫 번째인가

실물 원소판은 **식탁 한가운데 놓인 공용물**이다. 한 사람이 밀면 모두가 본다.
셋 중 공유 가치가 가장 크고, 상태가 가장 작다 — 여섯 값이 전부다.

작다는 것이 중요하다. **틀렸을 때 통째로 다시 받아도 되고**, 충돌해도 사용자가
눈으로 확인할 수 있다.

---

## 손가락이 먼저다

왕복을 기다렸다가 그리면 탭할 때마다 늦게 반응한다. 서버가 멀면 더하다.

> **탭은 로컬에서 즉시 반영하고, 서버 확정이 뒤따라 덮는다.**

값이 3단계뿐이라 뒤늦게 덮여도 사용자가 이해할 수 있다 — 남이 동시에 만졌구나로
읽힌다. 이것이 축 ①의 커밋 단위 동기화와 갈리는 지점이다(SPEC 5.4).

**끄는 동작도 마찬가지다.** 손을 떼기 전에는 보내지 않는다. 끄는 내내 보내면
초당 수십 번이 되고, 어차피 중간값은 의미가 없다.

---

## 무엇이 공유되고 무엇이 안 되는가

| | 공유 |
|---|---|
| 원소 6개의 상태 | **된다** |
| 어떤 원소를 보이게 했는지(위젯 설정) | 안 된다 — 개인 것 |
| 위젯 배치·크기·툴바 위치 | 안 된다 — 개인 것 |
| 고급 효과 켬/끔 | 안 된다 — 기기 성능 문제 |

**남이 원소 넷만 켜 두었다고 내 화면에서 둘이 사라지면 안 된다.** 공유되는 것은
상태값이지 보기 설정이 아니다.

트래커를 **두 개 놓았다면 둘 다 같은 상태를 본다.** 상태는 전투에 하나뿐이고
위젯은 그것을 비추는 창일 뿐이다.

---

## 할 일

### 상태 잇기

- [ ] 전투에 참여 중이면 원소 스토어가 서버 상태를 따른다.
- [ ] 참여 중이 아니면 **지금 그대로** 메모리 전용. 코드 경로가 갈리는 곳을 좁게 둔다.
- [ ] 탭·드래그는 로컬 즉시 반영 후 보낸다.
- [ ] 서버에서 온 값이 로컬과 다르면 서버를 따른다.
- [ ] 보내기는 **손을 뗀 뒤 한 번.**

### 강등과 복귀

- [ ] 끊기면 로컬로 계속 쓴다.
- [ ] 돌아왔을 때 서버와 같으면 아무 말 없이 넘어간다.
- [ ] 다르면 **한 번 묻는다** — "서버에 맞출까, 내 것으로 덮을까".
  - 여섯 값을 나란히 보여준다. 무엇이 다른지 보이지 않으면 고를 수 없다.
  - 묻는 동안에도 판은 돈다. 화면을 막지 않는다.

### 표시

- [ ] 지금 공유 중인지 행낭에서 항상 보인다(N4에서 만든 표시를 쓴다).
- [ ] 남이 바꾼 것이 반영될 때 **알아챌 만큼만** 티를 낸다. 내가 민 것과 남이 민
      것이 구별되지 않으면 유령이 미는 것처럼 보인다.

### 도메인 로직

- [ ] 병합 규칙을 **순수 함수로** 떼어 Vitest로 검증한다(SPEC 4.1).
  - 로컬만 바뀜 / 서버만 바뀜 / 둘 다 바뀜 / 같은 원소를 서로 다르게
  - 강등 중 여러 번 바꾼 뒤 복귀
- [ ] 보내기 묶음(디바운스) 규칙도 순수 함수로.

---

## 검증

- [ ] 두 창에서 한쪽이 원소를 밀면 다른 쪽이 따라온다.
- [ ] 동시에 같은 원소를 밀어도 둘이 같은 값으로 수렴한다.
- [ ] 끄는 동안에는 보내지 않고 손을 뗄 때 한 번 보낸다(네트워크 탭으로 확인).
- [ ] 서버를 끊고 원소를 바꾼 뒤 다시 붙이면 물어본다.
- [ ] 물어보는 화면에서 양쪽 값이 다 보인다.
- [ ] **전투에 참여하지 않으면 종전과 똑같이 동작한다.** 서버가 꺼져 있어도.
- [ ] 남이 원소 표시 설정을 바꿔도 내 화면의 원소 수는 그대로다.
- [ ] 트래커를 둘 놓으면 둘 다 같은 상태를 본다.
