# M9 — 위젯 설정과 원소 트래커 고르기  ✅ 완료 (2026-07-31)

위젯마다 **인스턴스별 설정**을 갖게 하고, 그 첫 사용처로 원소 트래커에
"어떤 원소를 보일지"를 붙인다.

**선행:** M8

---

## 설계

### 설정은 어디에 사는가

**사용자 설정이다.** 위젯 배치와 같은 성격이므로 `localStorage`에 남는다
(SPEC 5.2). 뽑은 카드·원소 상태 같은 도구 런타임과는 다르다.

**인스턴스 단위로 저장한다.** 같은 위젯을 여러 개 놓고 각기 다르게 설정할 수
있어야 한다는 요구가 그대로 자료구조가 된다.

```ts
interface SatchelSettings {
  ...
  /** instanceId → 그 위젯의 설정. 모양은 위젯마다 다르다. */
  widgetSettings: Record<string, unknown>
}
```

**레이아웃 안이 아니라 바깥에 둔다.** 레이아웃은 열 수마다 따로 저장되지만
`instanceId`는 파생을 거쳐도 그대로 유지되므로, 설정을 레이아웃 안에 넣으면
열 수마다 복제되어 서로 어긋난다.

### 타입을 어디까지 밀어붙일 것인가

레지스트리는 서로 다른 모양의 설정을 한 배열에 담는다. 제네릭으로 끝까지
끌고 가면 등록·조회·저장 모든 곳에 타입 매개변수가 번진다.

**경계에서만 좁힌다.** 레지스트리는 `unknown`으로 들고 있고, 각 위젯이
`sanitize`로 자기 모양을 보장한다. 저장소에서 읽은 값은 늘 `sanitize`를
거치므로 위젯 컴포넌트는 안심하고 자기 타입으로 받는다.

```ts
interface WidgetSettingsSpec {
  /** 없거나 망가진 값에서도 반드시 쓸 수 있는 값을 낸다. */
  sanitize: (raw: unknown) => unknown
  Editor: ComponentType<{ value: unknown; onChange: (next: unknown) => void }>
}
```

### 크기 제약이 설정에 딸린다

원소를 둘만 고르면 긴 쪽이 2칸이면 된다. 즉 **제약이 상수가 아니라 설정의
함수**가 된다.

`isSizeAllowed(size)` → `isSizeAllowed(size, settings)`.

**크기가 바뀔 수 있는 모든 길목이 설정을 함께 넘겨야 한다** — 크기 조절(M6),
열 수 파생(M3), 새로 놓기(M4). M8에서 이 훅을 세 곳에 연결했는데, 이번에는
그 세 곳이 전부 인스턴스 설정을 찾아 넘겨야 한다.

## T9.1 — 설정 저장과 스토어

- [x] `SatchelSettings.widgetSettings` 추가. 저장소 검증에 포함한다.
- [x] 위젯을 치울 때 그 인스턴스의 설정도 함께 지운다. 안 지우면 저장소에
      영원히 남는다.
- [x] 되돌리기가 설정까지 되돌릴지 정한다. **되돌리지 않는다** — 이력은 배치에
      대한 것이고, 설정까지 얽으면 무엇이 되돌려졌는지 알기 어렵다.
- [x] `settingsFor(instanceId, definitionId)` — 늘 `sanitize`를 거친 값을 낸다.

---

## T9.2 — 설정 규약과 팝업

- [x] `WidgetDefinition.settings?: WidgetSettingsSpec`
- [x] `WidgetProps.settings: unknown` — 위젯이 자기 타입으로 좁혀 쓴다.
- [x] 편집 모드에서 **설정을 지원하는 위젯에만** 톱니바퀴 버튼을 낸다.
      제거(×) 버튼 바로 왼쪽.
- [x] 팝업 — 가운데 띄우는 모달. 폰에서도 쓸 수 있어야 하므로 위젯에 붙이는
      팝오버보다 안전하다.
- [x] `Esc`·바깥 누르기·닫기 버튼으로 닫는다. 초점을 가둔다.
- [x] 설정 변경은 **즉시 반영·즉시 저장**한다. 확인 버튼을 두면 되돌리기와
      의미가 겹친다.

## T9.3 — 슬라이드 토글

- [x] 재사용 가능한 토글 하나. 원소 6종 + 전체 토글에 쓰고, 나중 위젯도 쓴다.
- [x] 비활성 상태를 표현할 수 있어야 한다(전체 표시가 켜져 있을 때 하위 항목).
- [x] 키보드로 켜고 끌 수 있어야 한다.

---

## T9.4 — 원소 트래커 설정

- [x] `maxInstances: 1` 제거. 여러 개 놓을 수 있다.
- [x] 설정 모양

```ts
interface ElementSettings {
  showAll: boolean            // 기본 true
  visible: Record<string, boolean>
}
```

- [x] 편집 화면 — 맨 위에 "모든 원소 표시", 아래에 원소 6종.
- [x] 전체 표시가 켜져 있으면 하위 항목은 조작 불가. **아이콘도 흑백으로** 두어
      지금 개별 선택이 무의미하다는 것을 보여준다.
- [x] 켠 원소만 위젯에 그린다.
- [x] **마지막 하나는 끌 수 없다.** 원소가 하나도 없는 트래커는 쓸모가 없고,
      크기 제약도 0이 되어 의미를 잃는다.

---

## T9.5 — 크기 제약을 설정에 맞춘다

- [x] `isElementTrackerSizeAllowed(size, settings)` — 긴 쪽이 **보이는 원소 수**
      이상이면 된다.
- [x] 원소를 줄이면 제약이 느슨해지고, 늘리면 조여진다. **늘렸을 때 지금 크기가
      제약을 못 넘기면** 어떻게 할지 정한다 — 파생 규칙이 이미 그런 위젯을
      버리므로, 설정 화면에서 막거나 자동으로 늘려야 한다.

## T9.6 — 검증

- [x] 설정 저장·복원, 인스턴스별로 다른 설정
- [x] 위젯 제거 시 설정도 지워지는지
- [x] 원소 2개만 켜고 2×1로 줄일 수 있는지
- [x] 전체 표시를 켜면 하위 토글이 잠기는지
- [x] 저장소에 쓰레기를 넣어도 기본값으로 뜨는지

## 진행하며 정한 것

**설정 화면의 그림은 노드가 아니라 URL로 받는다.** 처음에는 `icon: ReactNode`로
두고 안쪽에 span을 하나 더 넣었는데, `background-size: contain`이 걸린 요소와
그림이 놓인 요소가 갈려 **고유 크기 600pt짜리 SVG의 좌상단 투명 귀퉁이만**
보였다. 그림이 놓이는 요소에 크기 규칙이 함께 걸려야 한다.

**톱니바퀴는 테두리에서 뻗은 선만으로는 해처럼 읽힌다.** 톱니를 테두리와 같은
굵기로 짧게 붙여 바퀴에서 돋아난 것으로 보이게 했다.

**되돌리기는 설정을 되돌리지 않는다.** 이력은 배치에 대한 것이고, 설정까지
얽으면 무엇이 되돌려졌는지 알기 어렵다.
