# M8 — 원소 트래커 위젯  ✅ 완료 (2026-07-31)

행낭의 **첫 실제 도구**. 6원소의 상태를 눈으로 보고 손으로 옮긴다.

Test 위젯이 "빈 사각형이 격자에 놓이는가"를 확인했다면, 이쪽은 **위젯 규약이
진짜 도구를 담을 수 있는가**를 확인한다. 여기서 드러나는 부족한 점이 나머지
두 도구(공격 보정 덱·주도권 정렬)의 설계에 그대로 반영된다.

**선행:** M7
**성격:** 이번 마일스톤은 **Creator Pack 에셋을 처음 들인다.** 라이선스 절차가
코드보다 먼저다.

## 게임 규칙 확인 (참고)

실물 원소판은 원소마다 **Strong → Waning → Inert** 세 칸이 있고 토큰이 그 사이를
옮겨 다닌다. 라운드가 끝나면 Strong은 Waning으로, Waning은 Inert로 내려간다.
소비하면 어디에 있든 곧장 Inert로 간다.
([Gloomhaven Wiki](https://gloomhaven.fandom.com/wiki/Elements),
[Dized Rules](https://rules.dized.com/game/I7lEsCGOS2-zgol-ZRNf3g/QqqZSgPQSNWoHi88TtDLsg/elemental-infusion))

**우리는 규칙을 돌리지 않는다.** SPEC 1장대로 룰 엔진이 아니므로 라운드 종료를
자동으로 처리하지 않는다. 사용자가 손으로 옮기는 것을 **거들기만** 한다.

| 이 문서의 이름 | 게임 용어 |
|---|---|
| 활성1 | Strong |
| 활성2 | Waning |
| 비활성 | Inert |

## T8.1 — 위젯 크기 제약을 확장한다

요구사항은 **"가로 혹은 세로가 최소 6격자"**다. 지금 `WidgetDefinition.minSize`는
`{w, h}` 하나뿐이라 이 **OR 조건을 표현할 수 없다.** `minSize: {w:6, h:6}`으로 두면
6×6 미만이 전부 막혀 세로 막대(1×6)도 못 만든다.

- [x] `WidgetDefinition`에 크기 검증 훅을 추가한다.

```ts
/** minSize/maxSize로 표현할 수 없는 제약. 통과하지 못하면 그 크기로 확정하지 않는다. */
isSizeAllowed?: (size: { w: number; h: number }) => boolean
```

- [x] M6의 크기 조절과 M3의 파생·재배치가 이 훅을 함께 본다. 한 군데라도 빠뜨리면
      규칙을 어긴 크기가 저장된다.
- [x] 훅이 있는 정의는 `defaultSize`가 스스로 통과하는지 레지스트리 검증에 추가한다.

**대안을 검토했으나 버린 것:** `minSize`를 배열로 받아 "이 중 하나를 만족"으로
푸는 방법. 조건이 하나 늘 때마다 자료구조를 고쳐야 하고, 실제로는 "긴 쪽이 6 이상"
같은 관계식이 필요해진다. 함수 하나가 단순하다.

**수용 기준:** 6×1은 되고 5×5는 안 된다. 크기 조절 중 허용되지 않는 크기는
무효 표시가 나고 확정되지 않는다.

## T8.2 — 배치 계산 (순수 함수)

전부 순수 함수로 두고 Vitest로 검증한다. 화면 코드가 좌표 산술을 다시 하지 않는다.

```
computeElementLayout(widgetSize, cellSize, gap) => ElementLayout
```

- [x] **방향** — 가로가 길면 원소를 수평으로, 세로가 길면 수직으로 늘어놓는다.
      정사각형일 때의 기본 방향을 정한다(수평을 권한다 — 실물 원소판이 가로다).
- [x] **아이콘 크기** — 격자 한 칸 정도. 칸을 꽉 채우지 않고 여백을 남긴다
      (0.7~0.8칸 정도). 아이콘은 격자에 스냅하지 않는다.
- [x] **슬라이딩 가능 여부** — 배치 방향과 수직인 쪽 공간이 **아이콘 크기의 2배
      이상**이면 슬라이딩한다. 아니면 제자리에서 상태만 바뀐다.
- [x] **세 칸의 좌표** — 슬라이딩할 때 각 상태가 놓일 위치.
- [x] 원소 6칸을 균등 배분하고 남는 여백을 양 끝에 나눈다.

**수용 기준 (테스트):**
- 6×1과 1×6에서 방향이 각각 수평·수직으로 나온다
- 6×1(수직 여유 1칸)은 슬라이딩 불가, 6×3은 가능
- 원소 6개의 슬롯이 겹치지 않고 위젯 안에 들어온다
- 아이콘 크기가 위젯 크기에 비례해 커지되 상한이 있다

## T8.3 — 상태 모델

- [x] `'inert' | 'strong' | 'waning'` 여섯 개.

## T8.4 — 아이콘과 상태별 표현

- [x] 비활성: **흑백.** `filter: grayscale(1)`로 처리하면 아이콘을 한 벌만 두면 된다.
      명도도 함께 낮춰 확실히 죽은 것으로 보이게 한다.
- [x] 활성2: **컬러.**
- [x] 활성1: 컬러 + **아이콘 색에 맞춘 glare 애니메이션.**
- [x] 원소별 색을 정한다. Creator Pack 아이콘의 고유색을 그대로 쓰되, glare에 쓸
      대표색을 원소마다 상수로 뽑는다.
- [x] `prefers-reduced-motion`에서 glare를 끈다.

**원소별 고유 효과(불꽃·덩쿨·소용돌이 등)는 이번 범위 밖이다.** 먼저 공통 glare로
세 상태가 확실히 구분되는지 확인하고, 그 위에 얹는다. 지금 넣으면 여섯 가지 효과를
동시에 손보게 되어 무엇이 문제인지 알기 어렵다.

## T8.7 — 테마

배경은 **실물 원소판의 조작감**을 옮긴다. 후보는 아래 셋이며 하나를 고른다.

**A. 홈에 끼워진 판이 미끄러지는 트랙** (권장)
원소마다 가로로 파인 홈이 있고, 원소가 새겨진 석판이 그 안을 미끄러진다.
홈에 세 군데 걸림 자국(detent)이 있어 **건드리기 전에도 상태가 셋이라는 것이
보인다.** 슬라이딩이 안 되는 좁은 크기에서는 홈이 사라지고 석판만 남아 그대로
성립한다.

**B. 석판 위의 룬돌**
넓은 석판에 원소마다 얕은 홈 세 개가 파여 있고 룬돌을 옮겨 놓는다. A보다
장식적이고 덜 기계적이다. 대신 "여기를 밀 수 있다"는 신호가 약하다.

**C. 각인만 하는 판**
움직임 없이 각인이 빛나고 꺼진다. 좁은 크기 전용 표현으로는 맞지만, 넓을 때
공간이 남는다.

- [x] 하나를 골라 구현한다. 좁은 크기와 넓은 크기 **양쪽에서 성립하는지** 함께 본다.
- [x] 기존 팔레트만 쓴다. 원소 트래커 전용 색을 새로 만들지 않는다 — 단, 원소
      고유색은 아이콘에서 오는 것이라 예외다.

## 열린 질문

1. **상태의 좌우 방향.** 요구사항에 `(좌: 비활성, 중: 활성2, 우: 활성2)`로 적혀
   있는데 마지막이 오타로 보인다. 실물 원소판은 Strong → Waning → Inert 순으로
   내려가므로 **좌: 활성1**이 자연스럽지만, "왼쪽이 꺼짐, 오른쪽으로 갈수록 강함"인
   전력계 은유도 말이 된다. **확인 필요.**
2. 정사각형(예: 6×6)일 때 기본 방향 — 수평을 권한다.
3. 전부 비활성으로 되돌리는 버튼을 위젯 안에 둘지. 라운드 정리에 편하지만
   위젯이 도구가 아니라 컨트롤 패널이 되어 간다.
4. `maxInstances: 1`로 둘지. 원소 트래커가 둘일 이유는 없어 보이지만, 두 파티를
   동시에 볼 일이 생길 수도 있다.
