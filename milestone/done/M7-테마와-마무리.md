# M7 — 테마와 마무리  ✅ 완료 (2026-07-31)

기능이 다 붙은 보드를 글룸헤이븐 결로 마감하고, 접근성과 반응형을 검증한다.

앞 마일스톤들에서 테마 토큰을 쓰되 세부는 미뤄뒀다. **여기서 한 번에 맞춘다** —
화면이 다 나온 뒤에 보는 편이 낫기 때문이다.

**선행:** M6
**예상 산출물:** CSS 위주. 검증 기록.

---

## 테마 방향

웰컴 화면이 **간판**이라면 행낭은 **연장을 늘어놓은 작업대**다. 같은 팔레트를 쓰되
장식을 덜고 기능을 앞세운다.

기존 토큰(`src/index.css`)을 그대로 쓴다. **행낭 전용 색을 새로 만들지 않는다** —
팔레트가 갈리면 두 화면이 다른 앱처럼 보인다.

| 요소 | 방향 |
|---|---|
| 보드 바탕 | 웰컴보다 어둡고 평평하게. 위젯이 주인공이므로 바탕이 나서지 않는다 |
| 격자 | 아주 옅은 놋쇠 선. 편집 중에만 보이므로 존재는 분명하되 눈이 아프지 않게 |
| 위젯 껍데기 | 웰컴 카드의 모서리쇠·안쪽 하이라이트를 축소해 재사용 |
| 툴바 | 가죽 띠. 보드와 경계가 분명해야 한다 |
| 활성 상태 | 황동 골드(`--sl-gold`) |
| 무효·경고 | 불씨(`--sl-ember`) — 지금까지 쓰지 않은 토큰이라 여기서 처음 일한다 |

## T7.4 — 문구

화면에 나가는 모든 낱말을 `WelcomePage.tsx` 주석의 문체 원칙에 맞춘다.

- [x] **수식어를 붙이지 않는다**
- [x] **동작을 설명하지 않는다**
- [x] **탁자 위 현실을 가리키지 않는다** — "위젯", "그리드", "드래그" 같은 말이

## T7.6 — 반응형 실측

CDP `Emulation.setDeviceMetricsOverride`로 검증한다. `--window-size`는 뷰포트를
바꾸지 못한다.

| 기기 | 크기 | 확인할 것 |
|---|---|---|
| iPhone SE | 375×667 | 4열, 툴바 상단, 가로 넘침 없음 |
| iPhone 15 | 393×852 | 4열, 툴바 상단 |
| 갤럭시 S24 | 360×780 | 4열, 툴바 상단 |
| 폰 가로 | 852×393 | 툴바 좌측, 행 2 이상 |
| iPad 세로 | 820×1180 | 8열, 툴바 좌측 |
| iPad 가로 | 1180×820 | 10열, 툴바 좌측 |
| 데스크톱 | 1440×900 | 12열, 툴바 좌측 |

각 크기에서:

- [x] `document.documentElement.scrollWidth === innerWidth`
- [x] 보드가 뷰포트 안에 들어온다(세로 스크롤 없음)
- [x] 격자 열 수가 표대로다
- [x] 툴바가 안전 영역을 침범하지 않는다
- [x] Test 위젯을 놓고 회전시켰을 때 파생 규칙(M3 T3.4)이 동작한다
