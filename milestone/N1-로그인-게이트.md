# N1 — 로그인 게이트와 세 배포

**서버 없이 만들 수 있는 전부.** 게이트를 먼저 세워야 뒤따르는 화면들이 "로그인된
상태"를 전제로 설계된다. PocketBase는 N2에서 붙인다.

선행: 없음 · 정본: [`../SPEC.md`](../SPEC.md) 3.1 / 6.1 · 전체 그림: [N0](./N0-네트워킹-설계.md)

---

## 목표

1. 로그인하지 않으면 **공지 페이지 외에는 아무것도 열리지 않는다.**
2. 같은 코드에서 **세 배포**가 나온다 — `demo`(로그인 없음) / `mock`(로그인 있음 +
   가짜 백엔드) / `live`(로그인 있음 + 진짜 백엔드).
3. 인증의 **실체는 아직 없다.** 세션을 들고 있는 자리만 만들고, 실제 검증은 N2에서
   끼운다.

---

## 왜 이렇게 하는가

### 게이트의 기준은 '세션이 있는가'다

*'서버에 닿는가'로 두면 절대 원칙 3이 죽는다.* 라즈베리파이가 정전이거나 DDNS가
늦거나 지하라 신호가 없으면 **판 도중에 앱이 벽돌이 된다.**

그래서 이렇게 나눈다.

| 묻는 것 | 언제 | 없으면 |
|---|---|---|
| 이 기기에 유효한 세션이 있는가 | 앱을 열 때마다 | 로그인 화면 |
| 이 세션이 서버에서도 유효한가 | 네트워크가 될 때 틈틈이 | **아무 일도 없다** — 갱신에 실패하면 다음 기회에 다시 |

첫 로그인만 네트워크를 요구한다. 이후에는 저장된 세션으로 연다 — **인증에는**
네트워크가 필요 없다. 다만 화면 자체를 받아오는 것은 별개이며, 그것은 PWA
캐싱(Phase 3)의 몫이다. '하지 못한 것' 참조.

### 왜 세 배포인가

처음에는 둘로 적었다 — 공개 데모와 정식. 그러면 **로그인 화면을 배포된 페이지에서
볼 수가 없다.** 서버가 아직 없는 동안 폰으로 흐름을 만져보려면 "로그인은 있는데
백엔드는 가짜"인 자리가 필요하다. 그것이 `mock`이다.

`mock`은 공개 주소에 올라가므로 **시험판임이 화면에 박혀 있어야 한다.** 나중에
어느 쪽을 보고 있는지 헷갈리면 곤란하다.

### 배포는 빌드 시점에 가른다

런타임 분기로 두면 공개 번들에 **인증 코드와 서버 주소가 함께 실린다.** 라즈베리
파이 주소가 공개 번들에 박히면 그 자체가 집 서버를 광고하는 셈이다.

**플래그가 없으면 로그인을 요구하는 쪽이 기본이다.** 반대로 두면 설정 하나
빠뜨렸을 때 정식 배포가 활짝 열린다. `VITE_BASE`로 이미 두 번 덴 자리다 —
그때는 화면이 하얘지는 것으로 끝났지만 이번엔 조용히 열린다.

### 공지 페이지는 게이트 밖이다

Creator Pack의 출처표시 의무는 **로그인 여부와 무관하게 배포에서 발생한다**
(SPEC 13.1). 표기를 게이트 뒤에 숨기지 않는다. 규칙을 단순하게 — `#/notice`는
언제나 열린다.

## 할 일

### 빌드 플래그

- [x] `VITE_AUTH_MODE` 도입 — `demo`/`mock`/`live`. **없거나 모르는 값이면 `live`로
      친다.** 앞뒤 공백과 대소문자만 봐준다.
- [x] 워크플로에 값을 적고 왜 그 값인지 주석으로 남긴다. 지금은 `mock`이다 —
      서버가 없으므로 배포된 페이지에서 흐름만 만져본다.
- [x] 플래그를 읽는 자리를 **한 곳으로 모은다**(`src/features/auth/mode.ts`).
      여기저기서 `import.meta.env`를 직접 읽으면 기본값 규칙이 흩어진다.
- [x] 순수 함수로 떼어 Vitest로 검증 — 빈 값, 공백, 오타, 숫자, 객체에서 각각
      무엇이 나오는지 표로 못 박았다.

### 세션 보관

- [x] 세션을 담는 스토어를 만든다. 축 ②의 스토어와 **섞지 않는다.**
- [x] 보관 위치는 `localStorage`. IndexedDB는 축 ①의 것이다(SPEC 5.2의 선을 따른다).
- [x] 만료를 들고 있는다. 만료됐으면 있는 것으로 치지 않는다.
- [x] **아직 아무 서버와도 이야기하지 않는다.** `AuthAdapter` 하나가 바깥 경계이고,
      N2에서 그 안쪽만 갈아끼운다.

### 라우트 가드

- [x] 로그인하지 않은 상태에서 `#/`, `#/satchel` 등에 들어오면 로그인 화면으로 보낸다.
- [x] **가려던 곳을 기억했다가 로그인 후 그리로 되돌린다.** 바깥 주소로는 튕겨
      보내지 않는다.
- [x] `#/notice`는 언제나 통과시킨다.
- [ ] 플래그가 꺼진 빌드에서는 가드가 **통째로 빠진다.** 하지 못했다 — 지금은
      `guardRoute`가 `demo`에서 늘 통과를 돌려줄 뿐 코드는 번들에 남는다. 비밀이
      들어 있지 않아 새는 것은 없지만, 애초 적어둔 것과는 다르다.

### 로그인 화면

- [x] 글룸헤이븐 테마에 맞춘다. 기존 카드·툴바와 같은 팔레트.
- [x] 아이디·비밀번호 두 칸. 자동완성 속성을 제대로 준다(`username`,
      `current-password`) — 안 주면 폰에서 비밀번호 관리자가 안 뜬다.
- [x] 실패 메시지는 **무엇이 틀렸는지 알려주지 않는다.** "아이디가 없다"와
      "비밀번호가 틀렸다"를 가르면 계정 존재 여부가 새어 나간다.
- [x] 오프라인에서 첫 로그인을 시도하면 그렇다고 말해준다. **다만 시험하지
      못했다** — `mock`은 네트워크를 타지 않아 이 갈래로 갈 일이 없다. N2에서
      진짜 확인된다.

### 로그아웃

- [x] 세션만 지운다. **로컬 데이터는 지우지 않는다.**
- [ ] "이 기기에서 기록 지우기"를 **따로** 둔다. 하지 못했다 — 지울 기록(축 ①)이
      아직 없어 지금 만들면 빈 단추가 된다.
- [ ] 아직 동기화되지 않은 변경이 있으면 지우기 전에 알린다. (동기화가 생기는
      Phase 2 이후에 실제 동작.)

## 하지 않는 것

- **실제 인증.** N2에서 PocketBase를 붙인다. 지금은 세션을 넣고 빼는 자리까지.
- **회원가입.** 초대 링크와 함께 N3에서.
- **로컬 데이터를 계정에 묶기.** `ownerUserId`는 스키마에 이미 있다(구현 결정 3).
  실제로 채우는 것은 동기화를 만들 때다.

## 검증

빌드해서 `vite preview`로 띄운 뒤 브라우저로 확인했다. 화면을 눈으로 보는 것이
아니라 **어디로 튕기는지**를 봐야 하는 종류라 자동으로 돌렸다.

- [x] `demo` 빌드에서 로그인 없이 모든 화면이 열린다.
- [x] `mock` 빌드에서 `#/satchel`에 직접 들어가면 로그인 화면으로 가고, 로그인
      후 `#/satchel`로 돌아온다.
- [x] **플래그를 빼먹은 빌드에서 로그인을 요구한다.** ← 가장 중요한 검증
- [x] **오타(`오타`)를 낸 빌드에서도 로그인을 요구한다.**
- [x] 세 모드 모두에서 `#/notice`는 열린다.
- [x] 만료된 세션은 열리지 않고 저장소에서 지워진다.
- [x] 망가진 JSON이 들어 있어도 열리지 않는다.
- [x] 로그인한 뒤 새 탭을 열면 **바깥 호스트로 나가는 요청이 0건**이다 — 인증에
      네트워크를 쓰지 않는다는 뜻이다.
- [x] 실패 문구가 "없는 아이디"와 "짧은 비밀번호"에서 **같다.**
- [x] 나가기를 누르면 세션이 지워지고 로그인 화면으로 간다.
- [ ] 공개 빌드의 번들에 서버 주소가 들어 있지 않다. **아직 확인할 것이 없다** —
      서버 주소라는 게 생기지 않았다. N2로 넘긴다.
- [ ] 네트워크를 끊고 새로고침해도 열린다. **실패했다** — 아래 참조.

## 하지 못한 것

- **오프라인에서 앱을 띄우는 것.** 세션이 기기에 남으므로 **인증에는** 네트워크가
  필요 없다 — 새 탭을 열어도 바깥으로 나가는 요청이 0건인 것을 확인했다. 그러나
  **화면 자체를 받아오려면 아직 연결이 있어야 한다.** PWA 캐싱(Phase 3)이 붙어야
  "연결 없이 열린다"가 성립한다. 로그인 화면에 그렇게 적었다가 지웠다.
- **로컬 기록을 계정에 묶기.** `ownerUserId`는 스키마에 이미 있으나(구현 결정 3)
  실제로 채우는 것은 동기화를 만들 때다.
- **한 기기를 여러 사람이 쓸 때** 계정별로 로컬 데이터를 나누는 것.

## 열린 질문

- 세션 만료를 얼마로 둘 것인가. 짧으면 여행 중 막히고, 길면 잃어버린 기기가 오래
  열린다. 30~90일 사이로 보이나 N2에서 PocketBase의 토큰 수명과 함께 정한다.
- 한 기기를 여러 사람이 쓸 때(파티원끼리 폰 돌려보기) 계정별로 로컬 데이터를
  나눌 것인가. 동기화를 만들 때 정한다.
